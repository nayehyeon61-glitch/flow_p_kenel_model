# G-flow: member 마다 자기 상태의 G(x) 를 읽는 FM (2017, 2026-11-24)

감자 질문(2026-11-23): "G(x) 자체가 학습하도록 flow matching 을 설계할 수 있을까요, 이전 tendency core 가 G(x) 를
입력으로 넣어 학습한 것처럼?"

현재 FM(`devflow_lineW`)은 앙상블 평균의 G(x̄) 하나를 모든 member 가 같이 읽는다. G-flow(`devflow_gW`, 옵션
`--gmember --gdirect`, `fpk/devflow.py`)는 흐름의 매 걸음에서 member 자신의 상태로

    dG(z_τ) = G(x̄ + s z_τ) − G(x̄)          (기울기 없음, core 입력과 같은 RMS 정규화·clamp)
    v = σ v_θ(z_τ, τ | 조건, dG) + A ⊙ dG     (A: u, v, T, q 의 층마다 하나, 0 에서 시작)

를 계산한다. 나머지(source = kernel 편차, 직선 경로, 속도 회귀 손실, Heun 6걸음)는 현재 FM 과 같다. 같은 kernel
`devk_band_sphW`, 같은 core, 같은 학습 해(2008–2015), 600번. 2017 의 같은 60 IC × 8 member 로 채점해 IC 짝
bootstrap 2000회(`scripts/pair_nophys.py devflow_lineW devflow_gW`, `gflow_pair.json`). 변수별 표는 `gflow_vars.md`.

물리 통로 A 는 600번 뒤에도 모든 변수·층에서 |A| ≤ 0.05 (로그 `runs/fpk/devflow_gW.log` 의 g_direct). 선형 통로는 거의
쓰이지 않았고, 효과는 망 입력으로 들어간 dG 를 통해 나온다.

## 읽기

- 학습이 직접 줄이는 FM 손실은 모든 선행에서 낮아졌다(5~10일 3~3.5 %). member 자신의 dG 를 보면 속도장을 더 잘 맞춘다.
- 격자점마다의 주변분포 점수인 CRPS 는 그대로다. 이 점수는 대부분 평균(core 궤적)의 오차가 정한다.
- 분포 쪽은 조금씩 좋아졌다. IGN 은 3~10일에 유의하게 낫고(작음), 과대 분산이 줄었다(10일 s/s 1.12 → 1.10, z500 1.19 →
  1.13). 장 전체 구조를 보는 energy score b1 은 모든 선행에서 2~6 % 낮다(2016, 검정 안 함).
- 1·3일 평균은 0.2~0.3 % 나쁘다(유의, 작음).
- 정리: G(x) 를 member 마다 주면 FM 이 만드는 분포의 모양(과대 분산, 장 구조)이 나아지지만 점별 정확도는 바뀌지 않는다.
  G(x) 를 평균에 줄 때(core·kernel 단계)와 같은 모양의 결과다: 효과는 분포의 날카로움에서 보인다.
- 다음: 같은 kernel 에 G 를 전혀 안 주는 FM(`devflow_nogW --no-gcond`)으로 G(x̄) 몫까지 나누기, energy score 를 2017 에서
  IC 짝으로 검정하기.
